## Duplication findings — high

### D1. Policy-shaped history filters reimplement `evaluate` and already disagree

- Where: [utils/policy/policy_agent_utils.py](../../utils/policy/policy_agent_utils.py#L508-L610) (`_parse_int_field`, `_row_matches_history_filters`, `query_history`). The other matcher is [utils/policy/policy_evaluator.py](../../utils/policy/policy_evaluator.py#L155-L204) (`_parse_integer`, `_evaluate_condition`) via [utils/policy/policy_preview.py](../../utils/policy/policy_preview.py#L45-L87) and [utils/policy/policy_draft_tool.py](../../utils/policy/policy_draft_tool.py#L72-L80) (`history_evidence`).
- What is copied: the same conditions the drafter is told to use for "what would this rule have covered" — `stated_reason`, amount bounds, tenure, days since delivery, and `fraud_flag`. Amount bounds already call `parse_amount`. Reason, integer, and fraud comparisons are separate implementations.
- Drift already measured (item 3 above): `query_history` misses 6 aliased reasons. One of them, RF-2074, would auto-approve for $49 under an `arrived_damaged` rule. It also counts RF-2139 inside a 14-day window, which `evaluate` sends to review, and it undercounts clear fraud tokens by 4 (`N`, `false`). `history_evidence` follows `evaluate`, so the chat can quote one history total before build and a different total after `proposed`.
- Business impact: the manager hears the wrong exposure for a rule they may then save. Past decisions stay descriptive, and nothing here pays, but the two Part 2 evidence numbers are not the same match.
- Tests stay green because [tests/test_policy_agent.py](../../tests/test_policy_agent.py#L574-L591) locks exact `stated_reason == "changed_mind"`, while [tests/test_policy_evaluator.py](../../tests/test_policy_evaluator.py#L136-L141) locks alias folding. Neither compares the two counts.
- Minimal fix: keep `evaluate` as the only matcher for policy-shaped filters. Have `query_history` count rows `evaluate` would `approve_full` (same definition `history_evidence` already uses) and delete `_parse_int_field`. Reason folding stays in `normalize_reason`; integer parsing stays in `_parse_integer`.

### D2. The clarification detector is copied in the prompt, the guard, and the page

- Where:
  - Prompt values and marker names: [utils/policy/policy_agent.py](../../utils/policy/policy_agent.py#L169-L182).
  - Guard regexes: [utils/policy/policy_agent_utils.py](../../utils/policy/policy_agent_utils.py#L349-L357), used by `unrequested_question_topics` at lines 382–399.
  - Page copies: [app/pages/policy_management.py](../../app/pages/policy_management.py#L32-L58) (`_CLARIFY_MARKER`, `_THRESHOLD_PRESETS`, `_PRESET_MENTIONS`), used by `_pending_clarify_kind` at lines 71–94.
- What is copied: the same three threshold kinds, the same marker syntax, and the same preset lists (amount 25/30/50, tenure 6/12/24, delivery window 7/14/30). The scan found each regex twice, byte for byte. They match today.
- Drift scenario: change the prompt to offer $20/$40/$60, or add a marker kind, in only one of the three places. The guard then retries a question the page does not turn into a Quick pick, or the page shows a pick list the guard does not treat as a question. [tests/test_policy_agent.py](../../tests/test_policy_agent.py#L485-L494) covers only the guard.
- Business impact: the manager loses the pick list or the one-retry guard, so a threshold is easier to invent in chat. `policy_confirmation_blockers` still refuses a save offer when the number never appears in the manager's own text, so this does not by itself move money.
- Minimal fix: keep the marker regex, preset regexes, and preset values in `policy_agent_utils.py`. Import them from `policy_management.py`. Fill the three prompt bullets from those same values.

### O1. Two policy JSON writers treat `Decimal` differently

- Where: [utils/policy/policy_draft_tool.py](../../utils/policy/policy_draft_tool.py#L21-L52) (`_json_dumps`) and [utils/policy/policy_agent_utils.py](../../utils/policy/policy_agent_utils.py#L438-L439) (`json.dump(..., default=str)` in `save_policy_draft`).
